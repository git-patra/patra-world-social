## Important — new fix-boundary defect

### R3 — Post-deadline disconnect can contaminate the completed result's assistance flag

**Location:** `apps/server/internal/games/race/engine.go:285–295`, especially unconditional `k.BotAssisted = true` at line 293. Related correct timestamp gating is at `engine.go:138–148`.

The new metadata-only branch records assistance immediately, even when the notification's original timestamp is later than the race's natural end. The engine may still appear running because the owner has not processed its next tick. Installing that future-to-the-result metadata then makes the subsequent natural result include `BotAssisted=true`, although the timestamp-aware control selector correctly executes no bot input before finish.

**Confirmed trigger:** five humans; official start 4000; engine last advanced to 303950; install A's disconnect with original timestamp 304001; then advance to 304001. The race correctly finishes at 304000, but A's official result has `BotAssisted=true` despite zero bot-driven frames. This ordering is reachable because the actual owner installs pending disconnect metadata before its next advance. It needs only the ordinary gap between owner ticks, not a long outage.

The previous implementation first advanced to the event time, saw the terminal race, and returned before assigning this flag. Moving physics out of installation is correct, but moving the flag before its temporal boundary introduces this regression. Once finalized through the unchanged immutable result job, the inaccurate assistance history is durable. Position/time/phase are not changed in this probe; the defect is the official assistance flag.

**Fix:** retain metadata-only installation, but make the assistance flag effective only on the authoritative timeline before the applicable natural terminal result. Preserve an assistance flag from any earlier genuine takeover; do not clear legitimate prior assistance when ignoring a later disconnect. Do not reintroduce Tick inside the unordered metadata pass or restamp notifications.

**Required regression:** queue a disconnect whose original timestamp is after the absolute deadline while the owner remains on its preceding tick; then advance through the real lobby/adapter path. Require the original `FinishedAt`, unchanged positions/times and `BotAssisted=false` for the never-assisted actor, with one terminal event. Cover a shortened first-finish-plus-45-second cutoff as well, and retain pre-cutoff takeover/assistance, prior assistance, same-boundary natural-finish precedence and activation replay coverage. Checking the final `MatchResult` is necessary; verifying only no movement during metadata installation would miss this defect.

**Personal finish distinction:** an actor who individually finished earlier while other racers remain active could already receive `BotAssisted=true` on a later disconnect in the pre-fix implementation: the old disconnect loop did not exclude `k.Finished`. That is not a newly introduced R3 case and is not an additional blocking condition in this scoped rereview. If assistance is defined strictly over each actor's personal racing interval, track that existing edge separately. R3 is narrowly the new post-global-cutoff result contamination; a globally terminal all-finished result should likewise not absorb later metadata.
